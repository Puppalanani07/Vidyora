# Vidyora

Vidyora is an AI learning assistant backend built with Python and Flask.

## Run locally on Windows

The simplest startup option is to double-click `start.bat`. It activates `.venv`,
installs dependencies, starts Flask, and opens the app at `http://127.0.0.1:5000`.
Keep the terminal window open while using Vidyora.

To run it manually in PowerShell, activate the existing virtual environment:

```powershell
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks script activation, allow it for the current process and retry:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

Install dependencies and create `.env` from the example only if it does not exist:

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Set `GROQ_API_KEY` in `.env` to your Groq API key, with no quotes or spaces, to
enable generated tutor responses. The server reports whether the key is loaded
without printing it. Keep keys in this backend-only `.env` file; do not put them
in frontend code or commit `.env`. The `.gitignore` excludes `.env` and `.venv`.

Start the app (debug mode is enabled for local development):

```powershell
python app.py
```

The Flask API is available at `http://127.0.0.1:5000`. The UI can be served at
`http://127.0.0.1:5000/frontend/index.html` or opened with VS Code Live Server.
The frontend's API requests use the production Vercel API base URL configured
in `frontend/script.js`.

## Health check

With the server running, open a second PowerShell window and request the liveness endpoint:

```powershell
Invoke-RestMethod http://127.0.0.1:5000/health
```

The endpoint returns:

```json
{
  "ok": true
}
```

## Frontend

Open `http://127.0.0.1:5000/frontend/index.html` or use VS Code Live Server on
port 5500. Live Server requests are allowed by the Flask CORS configuration.

The frontend sidebar also includes History and Create Images/Create Videos pages. Image and video generation are placeholders. The simple `/chat` API does not save conversations, so chat history is unavailable when running `app.py`.

The chat UI sends `message` and `level` to `POST /chat`. Example PowerShell request:

```powershell
$body = @{
    message = "Why do seasons change?"
    level = "Beginner"
} | ConvertTo-Json

Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:5000/chat `
  -ContentType "application/json" `
  -Body $body
```

The response contains a `reply` generated by Groq using
`llama-3.3-70b-versatile`. Invalid requests return HTTP 400; API failures return
a JSON error. The backend never returns the API key.

## Deploy on Vercel

The `vercel.json` configuration routes every request to `api/index.py`, which
exports the Flask application. Set these environment variables in the Vercel
project settings:

- `GROQ_API_KEY` enables generated tutor responses.
- `MONGODB_URI` and `MONGODB_DATABASE` enable saved conversation history.

Vercel's Python runtime does not use Gunicorn; the existing Gunicorn dependency
is retained for the Render deployment configuration.

## Deploy on Render

1. Push this repository to GitHub.
2. In Render, choose **New** → **Blueprint** and select the repository. Render
   reads `render.yaml` and creates the free web service.
3. Set `GROQ_API_KEY`, `MONGODB_URI`, and `MONGODB_DATABASE` in the service's
   environment settings. `GROQ_API_KEY` is your Groq API key; `MONGODB_URI` is
   your MongoDB connection URI; `MONGODB_DATABASE` is the database name.
   Never commit secret values or add them to `render.yaml`.
4. For a manually created Python web service, use `pip install -r requirements.txt`
   as the Build Command and `gunicorn app:app --bind 0.0.0.0:$PORT` as the
   Start Command.
5. Deploy. Share the public `onrender.com` URL after the service is live. Free
   instances may sleep; the first request can take 30–60 seconds to wake up.
