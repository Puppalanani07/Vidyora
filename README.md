# Vidyora

Vidyora is an AI learning assistant backend built with Python and Flask.

## Run on Windows with PowerShell

Open PowerShell in the project directory and create and activate a virtual environment:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks script activation, allow it for the current process and retry:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

Install the dependencies and create a local `.env` file from the example:

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Edit `.env` and replace `replace_with_your_gemini_api_key` with your Gemini API key. Set `GEMINI_MODEL` to the Gemini model you want to use. Keep the key in this backend-only `.env` file: do not put it in frontend code, send it in API requests, or commit `.env`. The `.gitignore` excludes `.env`.

The `.env.example` also configures a local MongoDB server with `MONGODB_URI=mongodb://127.0.0.1:27017` and database `vidyora`. Make sure MongoDB Community Server is running before starting Flask. The app reuses one PyMongo client and reports a clear error if the URI/database settings are missing or MongoDB cannot be reached.

To use a non-default port in the current PowerShell session, set it before starting the app, for example:

```powershell
$env:PORT = "8000"
```

Start the Flask server:

```powershell
python run.py
```

The server listens at `http://127.0.0.1:5000` by default, or at the port set in `$env:PORT`.

## Health check

With the server running, open a second PowerShell window and request the health endpoint:

```powershell
Invoke-RestMethod http://127.0.0.1:5000/api/health
```

The endpoint returns:

```json
{
  "service": "Vidyora API",
  "status": "ok"
}
```

## Frontend

Start the Flask server with `python run.py`. To use VS Code Live Server, open `frontend/index.html`, choose **Open with Live Server**, and load the page from its localhost URL (usually `http://127.0.0.1:5500` or `http://localhost:5500`). Flask permits HTTP localhost and 127.0.0.1 origins on local ports to call `/api/*`, including when Live Server selects another port because its default is busy. Other hosts are not enabled. The frontend sends chat requests to `http://127.0.0.1:5000/api/chat`.

Alternatively, Flask also serves the frontend and API on the same origin at `http://127.0.0.1:5000`.

The frontend sidebar provides Home (chat), History, and Create Images/Create Videos placeholder pages. The image and video pages are explicitly placeholders because no generation APIs are connected. History is loaded from the backend conversation endpoints below; it displays an empty or unavailable state when MongoDB or the endpoints are unavailable. Use **New Chat** to start a separate conversation, or select a saved conversation to continue it.

The chat UI sends `message` and `learning_level` to `POST /api/chat`. Example PowerShell request:

```powershell
$body = @{
    message = "Why do seasons change?"
    learning_level = "beginner"
} | ConvertTo-Json

Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:5000/api/chat `
  -ContentType "application/json" `
  -Body $body
```

The response contains a `reply` generated by Gemini and a `conversation_id`. The first request creates a conversation; send that ID with later requests to append messages to the same conversation. Invalid requests return HTTP 400, a missing `GEMINI_API_KEY` returns HTTP 503, Gemini API failures return HTTP 502, timeouts return HTTP 504, and MongoDB failures return HTTP 503. Gemini requests have a 30-second timeout. The backend never returns the API key.

Saved conversation endpoints:

- `GET /api/conversations` lists the latest 50 conversations.
- `GET /api/conversations/<conversation_id>` loads a conversation and its messages.

For example, to verify MongoDB through the health endpoint, run `Invoke-RestMethod http://127.0.0.1:5000/api/health`; it returns `"mongodb": "connected"` when the database is reachable. In MongoDB Compass, connect to `mongodb://127.0.0.1:27017`, open the `vidyora` database, and inspect the `conversations` collection after sending a chat message.
